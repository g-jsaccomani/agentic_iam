# Agentic IAM Technical Architecture and Consultant Guide
**Google Cloud Consulting — L300/L400 System Architecture, Technical Design Document (TDD) & Deployment How-To**

> **Repository Deliverable:** [docs/06-Agentic-IAM-Technical-Architecture-and-Consultant-Guide.md](06-Agentic-IAM-Technical-Architecture-and-Consultant-Guide.md)

> **Executive Summary:** This L300/L400 System Architecture Specification and Technical Design Document (TDD) defines the enterprise reference architecture for the **Agentic IAM Accelerator (`agentic_iam_accelerator`)**. Engineered as a Zero-Trust, Clean-Slate Multi-User platform on Google Cloud Run, Google Agent Development Kit (`google-adk`), and Vertex AI (`gemini-3.1-pro-preview-customtools`, `GOOGLE_CLOUD_LOCATION=global`), it enforces a strict cryptographic boundary between the **AI Compute Plane** (`sa-agentic-iam-engine`, holding no permission on any customer resource in the default mode) and the **Isolated Per-User Target Inspection Plane** (`backend/session_vault.py`, executing 1-hour keyless Service Account impersonation via `iamcredentials.googleapis.com`). Each consultant's work is kept in a private, application-encrypted persistent workspace with consultant-chosen retention (Tenet 4); an optional persistent auto-renew, OFF by default, gives the platform standing read-only access to an Organization until the customer removes that binding, and revoking the consultant's own grant does not remove it (Tenet 3). Parts I, II, and III specify the 5-plane multi-agent architecture, NetworkX privilege-escalation graph math, IAM Recommender / Cloud Audit Log / Policy Simulator contracts, OpenTofu/Terraform HCL synthesis, Word/PDF report generation, and step-by-step deployment & consultation workflows.

## Part I — System Architecture Specification (5-Plane Clean-Slate Multi-Agent Topology & Zero-Trust Isolation)

## 1. Architectural Vision, Design Tenets & Customer Environment Template Manifest

Assessing and modernizing enterprise Cloud IAM and Cloud Identity posture requires simultaneous mastery of resource hierarchy inheritance, Cloud Identity group structures, transitive Service Account impersonation mechanics, 90-day audit usage telemetry, and Terraform/PAM engineering. An ungrounded LLM would hallucinate principals, permission counts, and attack paths, whereas a flat policy exporter cannot synthesize business personas, PAM JIT workflows, or modular HCL code. The Agentic IAM Accelerator resolves this with four core architectural tenets:

- **Tenet 1 — Strict Separation of AI Compute Plane vs. Target Inspection Plane (No Runtime Access to Customer Resources by Default):** On the host project, the Cloud Run runtime Service Account (`sa-agentic-iam-engine`) holds `roles/aiplatform.user` and `roles/logging.logWriter` to invoke Vertex AI Gemini models, plus access to the private workspace bucket and its master secret (Tenet 4). In the default and recommended mode it holds **no** permission on any customer resource (no customer GCP Organization, Folder, Cloud Asset Inventory, or BigQuery dataset); with the optional, OFF-by-default persistent auto-renew described in Tenet 3, the platform holds standing read-only access to that Organization until the customer removes that binding, and revoking the consultant's own grant does not remove it. `backend/tools/cai_collector.py` **never** falls back to `google.auth.default()` in web mode. Every new user boots into an empty **Clean-Slate Console** (`HTTP 412 Precondition Failed` on telemetry routes until explicit user-bound connection); a returning user sees only their own saved workspace, and users never see each other's data.
- **Tenet 2 — Hybrid Architecture: Deterministic Live Telemetry, Graph Math & Scoring with Evidence-Grounded LLM Reasoning:** Python and NetworkX tools (`cai_collector.py`, `directory_collector.py`, `graph_engine.py`, `recommender_tool.py`) collect 100% live GCP control-plane evidence, compute exact permission counts via the IAM Roles API, and calculate deterministic graph centrality (`betweenness_centrality`, `degree_centrality`) and topological simple paths (`nx.all_simple_paths`). Deterministic Python also computes the 18-control posture score. Five Gemini agents on Google ADK (`iam_coordinator` + 4 specialists) reason exclusively over those live payloads using Pydantic `output_schema` contracts to produce findings, attack-path analysis, least-privilege recommendations, a typed remediation plan and the executive narrative — zero synthetic fallbacks, zero hardcoded scores, and zero templated Python f-string narratives. Agent output is validated against the collected evidence (grounding), Terraform is rendered by deterministic code from the typed plan, and the agents can adjust a domain score by at most ±5 points. The agents run in-process in the Cloud Run service; the product is not deployed on Vertex AI Agent Engine and is not published in Gemini Enterprise.
- **Tenet 3 — 100% Agentless, Keyless & Zero-Plaintext Control-Plane Introspection:** Customer onboarding uses **keyless 1-hour Service Account impersonation** (`sa-iam-assessor@<CUSTOMER-SEED-PROJECT>.iam.gserviceaccount.com` via `generateAccessToken`, fully compliant with `constraints/iam.disableServiceAccountKeyCreation`). In the default and recommended mode the customer grants `roles/iam.serviceAccountTokenCreator` on `sa-iam-assessor` only to the named consultant user, and the tool mints 1-hour tokens with the consultant's own OAuth token. **Optional persistent auto-renew (OFF by default):** only if the deployment sets `IAM_ENABLE_PERSISTENT_DELEGATION=true` **and** the consultant ticks the explicit option when generating the onboarding kit, the kit additionally grants `roles/iam.serviceAccountTokenCreator` on `sa-iam-assessor` to the platform's Cloud Run runtime Service Account so sessions can be renewed without the consultant's token; the platform then holds standing read-only access to that Organization until the customer removes that binding, and revoking the consultant's own grant does not remove it (the offboarding snippet in the kit removes both bindings). The platform inspects IAM, Resource Manager, Cloud Identity, Recommender, and Audit Log metadata only — never accessing the customer's Secret Manager secret payloads, Cloud Storage objects, database rows, or private keys.
- **Tenet 4 — Thread-Safe Per-Session Isolation & Encrypted Per-User Persistent Workspace (`session_vault.py`, `workspace_store.py`):** Every authenticated user session receives a cryptographic `session_id` (`sid`) inside an HMAC-SHA256 signed `HttpOnly` cookie (`iam_consultant_ticket`, 8-hour lifetime). Tokens, caches, and generated deliverables (`.docx`, `.pdf`, `.png`, `.zip`, `.jsonl`) are partitioned per `session_id` via `contextvars.ContextVar` (propagated across `ThreadPoolExecutor` worker threads by `run_pool_map_with_context`). In addition, each signed-in consultant has a private workspace keyed to their Google identity that stores the connection record, the latest posture book, inventory and scan history so work survives browser closes; users never see each other's data. Storage is a private Cloud Storage bucket in the consultant's host project (uniform bucket-level access, public access prevention), and every stored document is encrypted by the application with AES-256-GCM using a per-user key derived from a master secret held in Secret Manager, in addition to Google's default encryption at rest. Retention is chosen by the consultant when connecting a customer: `0` days means nothing is persisted (session-only, in memory); otherwise 1 to 365 days (default 30). Expired data is deleted by the application and by a bucket lifecycle rule, and **Disconnect & Wipe** (`POST /api/v1/session/disconnect`) deletes the workspace data immediately.

## 2. Five-Plane System Architecture & End-to-End Data Flow (C4 Container & Component View)

The platform is architected across five decoupled horizontal planes that transform keyless user-delegated GCP telemetry into an auditable Identity Triad matrix, a NetworkX attack-path graph, bounded Cloud Audit Log change-impact estimates for Custom Roles/PAM entitlements, advisory (unvalidated) OpenTofu/Terraform bundles, and executive Word/PDF books:

1. **Plane 1 — Clean-Slate Presentation, Native Cloud IAP & Session Vault Layer (`backend/main.py`, `backend/identity_guard.py`, `backend/session_vault.py`, `frontend/app.py`):** FastAPI server protected at the edge by **Cloud Run Native Identity-Aware Proxy** (`--iap --no-allow-unauthenticated`, validating `X-Goog-IAP-JWT-Assertion` ES256 JWTs) plus signed `HttpOnly`, `Secure`, `SameSite=Lax` session cookies (`iam_consultant_ticket`). `zero_trust_session_isolation_middleware` binds the caller's `InspectionSession` via `ContextVar` on every HTTP request, exposing `/api/v1/session/status`, `/api/v1/session/connect` (6-probe pre-flight verification), `/api/v1/session/disconnect` (immediate wipe of the session and its stored workspace data), `/api/v1/org/hierarchy`, `/api/v1/onboarding/kit`, `/api/v1/triad`, `/api/v1/attack-paths`, `/api/v1/recommendations`, `/api/v1/iac`, `/api/v1/book`, `/api/v1/chat`, and deliverable download endpoints.
2. **Plane 2 — Multi-Agent Google ADK Orchestration Plane (`backend/agents/`):** Built natively on **Google ADK (`Runner`, `Agent`, `AgentTool`, `InMemorySessionService`)** and **Vertex AI (`gemini-3.1-pro-preview-customtools`, `location="global"`)**. `iam_coordinator` (`coordinator.py`) orchestrates four Gemini specialist agents in parallel (`asyncio.gather` during full book synthesis, or tool-delegated during multi-turn `/api/v1/chat`) and synthesizes `CoordinatorAgentOutput` (`overall_posture_score`, `maturity_tier`, `least_privilege_index`, `impersonation_resilience_score`, and CISO `executive_narrative_markdown`), recording full `AdkExecutionTelemetry` (`telemetry.py`) on every turn.
3. **Plane 3 — Deterministic Telemetry, NetworkX Graph & IaC Packaging Tool Plane (`backend/tools/`):** Strictly read-only evidence collectors and deterministic graph/packaging engines: (3A) Cloud Asset Inventory IAM bindings, resource discovery, Service Account key age, WIF pools, and effective Organization Policies (`cai_collector.py`), (3B) Cloud Identity Groups, Workspace Directory 2SV, Group RBAC ratio, and human Audit Log correlation (`directory_collector.py`), (3C) NetworkX directed privilege graph `nx.DiGraph`, centrality ranking, multi-hop simple paths, and high-DPI Matplotlib topology renderer (`graph_engine.py`), (3D) IAM Recommender, Policy Analyzer, IAM Roles API permission counter, bounded Cloud Audit Log sample collector (`is_sample`, `sample_size`, observed window, project coverage), existing Policy Simulator metadata reader (no replay executed), and advisory Terraform `.zip` packager (`recommender_tool.py`), and (3E) Zero-Key Customer Onboarding Kit & 6-point pre-flight validator (`onboarding_manager.py`).
4. **Plane 4 — Target Customer Google Cloud & Cloud Identity Control-Plane APIs:** Concurrent HTTPS REST introspection (authenticated strictly with `InspectionSession.effective_access_token` + `x-goog-user-project` quota header attribution) across `cloudasset.googleapis.com/v1`, `cloudresourcemanager.googleapis.com/v1 & v3`, `iam.googleapis.com/v1`, `iamcredentials.googleapis.com/v1`, `cloudidentity.googleapis.com/v1`, `admin.googleapis.com/admin/directory/v1`, `recommender.googleapis.com/v1`, `policyanalyzer.googleapis.com/v1`, `policysimulator.googleapis.com/v1`, and `logging.googleapis.com/v2`.
5. **Plane 5 — Session Deliverable, Encrypted Workspace & Optional Customer-Owned BigQuery Export Plane (`backend/report_generator.py`, `cai_collector.py`):** Compiles executive Word (`Agentic_IAM_Posture_Acceleration_Report.docx` via `python-docx`), executive PDF (`Agentic_IAM_Posture_Acceleration_Report.pdf` via `reportlab`), high-DPI Attack Path PNG (`attack_path_graph.png`), OpenTofu/Terraform remediation archive (`agentic_iam_terraform_remediation_bundle.zip`), and CSPR-aligned findings (`iam_posture_findings.jsonl`) for the user's isolated session; the latest posture book, inventory and scan history are additionally kept in the user's private encrypted workspace for the retention chosen at connect (Tenet 4; `0` days = nothing persisted). Zero rows are ever written to the host project's BigQuery; if the user explicitly specifies a customer-owned `<project>.<dataset>.<table>`, findings stream directly to the customer's BigQuery using the user's inspection token.

### 4.2 AI Safety, Anti-Hallucination & STRIDE Threat Mitigation Controls

- **Spoofing & Cross-Tenant Leakage Prevention (`identity_guard.py` & `session_vault.py`):** Cloud Run Native IAP verifies caller identity at Google's edge (`X-Goog-IAP-JWT-Assertion`), paired with an HMAC-SHA256 signed `HttpOnly` cookie binding `owner_email` to a 192-bit random `session_id`. `get_inspection_session(sid, caller_email)` enforces exact email ownership matching (`hmac.compare_digest`), purges expired entries automatically, and `run_pool_map_with_context` copies Python `contextvars` into every worker thread so concurrent scans never cross-contaminate tokens or caches. Persisted workspace documents are keyed to the owner's Google identity and encrypted with a per-user key (Tenet 4), so users never see each other's data.
- **Tampering & Privilege Escalation Prevention (Zero Host ADC Fallback):** In the default mode `sa-agentic-iam-engine` holds no permission on any customer resource, and `get_gcp_access_token_and_headers()` raises `PermissionError` (`HTTP 412`) whenever no active `InspectionSession` is bound — so host credentials cannot reach customer resources. With the optional persistent auto-renew enabled (OFF by default; Tenet 3), the runtime Service Account can mint read-only `sa-iam-assessor` tokens: the platform then holds standing read-only access to that Organization until the customer removes that binding, and revoking the consultant's own grant does not remove it.
- **Mitigating LLM Hallucinations (Integrity & Non-Repudiation):** Every Gemini specialist (`triad_analyzer`, `attack_path_agent`, `recommender_agent`, `iac_generator`, `iam_coordinator`) enforces a strict Pydantic `output_schema` (`TriadAgentOutput`, `AttackPathAgentOutput`, `RecommenderAgentOutput`, `IaCAgentOutput`, `CoordinatorAgentOutput`) and is instructed to cite only verbatim principals, roles, resources, permission counts, and NetworkX node IDs returned by live tools. Every execution records `AdkExecutionTelemetry` (`model_version`, `tokens`, `tool_calls`, `latency_ms`).

## 5. Non-Functional Requirements: Concurrency, Resilience, Observability & FinOps

- **Bounded Multi-Project Parallelism:** `cai_collector.py` queries selected projects and Organization Policy constraints concurrently via `run_pool_map_with_context` (6–10 worker threads) while `coordinator.py` executes the 4 specialist ADK planes concurrently via `asyncio.gather`, caching raw telemetry per `(session_namespace, canonical_scope)` for `60s` (`_TELEMETRY_CACHE_TTL_SECONDS`) so specialist agents reuse consistent snapshots without redundant API calls.
- **Automatic Quota-Project Self-Healing (`gcp_rest_request`):** Automatically attaches `x-goog-user-project` from `sess.quota_project_id`, infers project headers when APIs demand quota attribution, and retries cleanly without the header if a seed project lacks `serviceusage.services.use` on Organization-scoped endpoints.
- **Inactive Project Filtering:** `_get_org_project_lifecycle_sets` queries `cloudresourcemanager.googleapis.com/Project` states and automatically excludes `DELETE_REQUESTED` / `DELETE_IN_PROGRESS` projects from IAM posture findings and multi-project pickers.

## Part II — L400 Technical Design Document (5 ADK Agents, Live Collectors, NetworkX Graph & IaC Engine)

## 1. Engineering Context, IAM Modernization Breaking-Change Risks & Configuration Manifest

Modernizing cloud IAM across production estates fails when treated as a naive "delete unused roles" script due to four subtle operational failure modes that the Agentic IAM Accelerator explicitly models:

1. **90-Day Infrequent Batch & Disaster-Recovery Blind Spots:** Quarterly financial close jobs, disaster-recovery failover scripts, and annual certificate rotators may show `0` calls in a 30-day log window while still requiring permissions on day 90. `recommender_tool.py` combines 90-day `google.iam.policy.Recommender` ML insights with live Cloud Audit Log authorization telemetry and flags restricted changes as `REQUIRES_APPROVAL` when active external/admin usage is detected.
2. **Transitive Group & Convenience-Member Inheritance:** Removing a direct `user:` role has zero effect if that user remains inside a nested Cloud Identity group or holds `roles/editor` on a project whose BigQuery datasets still grant `projectEditor:<project_id>`. `graph_engine.py` explicitly links `projectOwner:` and `projectEditor:` convenience nodes to project-level primitive holders.
3. **Implicit Workload Attachment (`actAs` + Runtime Compute/Serverless Mutation):** A developer without `Owner` who holds `roles/iam.serviceAccountUser` + `roles/run.admin` or `roles/compute.instanceAdmin.v1` can deploy a revision/VM attached to the Default Compute Service Account (`-compute@developer.gserviceaccount.com`) and mint tokens from the metadata server. `graph_engine.py` connects both explicit SA bindings and project-wide SA reach edges across all active SAs in the project.
4. **Organization Policy Lockout Sequence:** Enforcing `constraints/iam.disableServiceAccountKeyCreation` or `constraints/iam.allowedPolicyMemberDomains` without staged Terraform variables and Policy Simulator review can block automated CI/CD pipelines. `iac_generator` produces a typed remediation plan that deterministic code renders into parameterized `variables.tf` and `org_policies.tf` modules so teams test in folder/project canary scopes first.

## 3. Deep Specification of Core Analytical Engines

### 3.1 Flexible Scope Parser (`parse_assessment_scope` in `cai_collector.py`)
Supports three canonical scope modes normalized seamlessly across every API route and ADK tool:
- **Organization-Wide (`ORG_ALL`):** `organizations/<ORG_ID>` — discovers all `ACTIVE` child projects, filters out `DELETE_REQUESTED` projects, collects Organization-wide CAI bindings/resources (`readMask=*`), and evaluates Organization Policies at the Organization root.
- **Organization Multi-Project Subset (`ORG_SELECTED_PROJECTS`):** `organizations/<ORG_ID>/projects:<p1>,<p2>,...` — collects leaf bindings and resources in parallel across the exact selected projects while **preserving inherited Organization-level IAM bindings** (`CLOUD_RESOURCE_MANAGER_V3_ORG_INHERITED`) and Organization Policy context!
- **Folder Scope (`FOLDER`):** `folders/<FOLDER_ID>` — evaluates folder-scoped CAI telemetry and effective folder Organization Policies.

### 3.2 NetworkX Directed Privilege & Escalation Graph (`graph_engine.py`)
1. **Node Taxonomy:** Instantiates typed `AttackPathNode` vertices (`user`, `external_user`, `group`, `service_account`, `workload`, `role`, `resource`) with severity promotion (`_merge_severity`).
2. **Edge Semantics:** Models (a) direct IAM role grants over resources and Service Accounts, (b) runtime `Attached Runtime SA` edges (`iam.serviceAccounts.implicitMetadataToken`) from GCE VMs and Cloud Run services to their attached Service Accounts, (c) `projectOwner:<pid>` and `projectEditor:<pid>` convenience ACL inheritance edges, and (d) project-scoped `SA_IMPERSONATION_OR_EXECUTION_ROLES` (`TokenCreator`, `serviceAccountUser`, `serviceAccountKeyAdmin`, `serviceAccountAdmin`, `compute.admin`, `instanceAdmin.v1`, `run.admin`, `cloudfunctions.admin/developer`) fanning out to active Service Accounts in that project.
3. **Centrality & Path Extraction:** Calculates `nx.betweenness_centrality(G)` and `nx.degree_centrality(G)` (`combined_chokepoint_score = (0.6 * C_B + 0.4 * C_D) * 100`) and extracts bounded simple paths (`nx.all_simple_paths(..., cutoff=4)`) containing at least one escalation edge for reasoning by `attack_path_agent`.

### 3.3 Complete 7-Section Executive Deliverable Synthesis (`report_generator.py`)
Generates six synchronized artifacts inside the user's isolated `session_export_dir` with **zero truncated tables or HCL blocks**:
- **`Agentic_IAM_Posture_Acceleration_Report.docx`** (`python-docx`) & **`Agentic_IAM_Posture_Acceleration_Report.pdf`** (`reportlab` Platypus): Complete 7-section executive & engineering books containing (1) Executive Narrative, Posture Scorecard & 18-Control Framework Matrix, (2) Identity Triad Matrix & Complete Findings Register, (3) Full Accounts, Service Accounts, SA Keys, Secret Manager Metadata, Cloud KMS CryptoKeys & SoD, API Keys, Custom Roles, WIF & Organization Policies Ledgers, (4) NetworkX Attack Path Graph, Choke-Point Centrality Ranking & Escalation Chains, (5) Least-Privilege Right-Sizing & PAM JIT Entitlements, (6) `Estimativa de impacto e bundle Terraform consultivo (não validado)` with bounded Cloud Audit Log sample evidence & all 5 advisory Terraform HCL modules (`main.tf`, `variables.tf`, `iam.tf`, `pam_entitlements.tf`, `org_policies.tf`), and (7) Phased 3-Wave Roadmap & Google ADK Tool Execution Audit Log.
- **`accounts_keys_secrets_inventory.json`**: Structured JSON export of all 32 KPIs and 9 live credential/vault ledgers (`GET /api/v1/download/inventory-json`).
- **`attack_path_graph.png`** (`matplotlib` Agg 220 DPI): Left-to-right layered multipartite layout highlighting escalation edges in crimson.
- **`agentic_iam_terraform_remediation_bundle.zip`**: Ready-to-inspect 5-file advisory HCL archive (unvalidated; validate via Policy Simulator and `terraform plan` in customer CI/CD).
- **`iam_posture_findings.jsonl`**: CSPR-compatible `GcpIamPostureFinding` records with `framework_citations` (not exported to BigQuery unless the user supplies `optional_customer_bq_table`).

### 3.4 Hybrid 18-Control Framework Scoring Engine (`posture_scoring_engine.py`)
Combines deterministic control-plane mathematics with bounded Google ADK contextual reasoning across **five authoritative security benchmarks** (*Google Cloud Security Foundations Blueprint*, *NIST SP 800-53 Rev. 5*, *NIST CSF 2.0*, *CIS Google Cloud Platform Benchmark v3.0*, and *CISA Zero Trust Maturity Model v2.0*):
1. **Layer 1 — Deterministic 18-Control Baseline (`95%` Mathematical Anchor):** Computes exact `numerator / denominator` ratios across 5 weighted domains (`22% Internal + 18% External + 22% Workload + 20% Least-Privilege + 18% Graph Resilience = 100%`).
2. **Layer 2 — Bounded Agentic Contextual Calibration (`[-5.0, +5.0]` pts max per domain):** Each Google ADK specialist (`triad_analyzer`, `attack_path_agent`, `recommender_agent`) calls `evaluate_iam_framework_scorecard`, inspects contextual nuances, and outputs a bounded `agentic_calibration_delta` + mandatory framework-cited `agentic_calibration_rationale`.
3. **Layer 3 — NIST / CISA Critical Exposure Ceiling (`<= 84.0%` Hard Gate):** Prevents false `Zero-Trust Accelerated (>= 85%)` classification whenever active anonymous public IAM bindings (`allUsers`/`allAuthenticatedUsers`) or aged (`>90d`) static Service Account keys exist without preventive Organization Policy enforcement.

### 3.5 Accounts, Keys, KMS & Secrets Vault Engine (`asset_key_secret_inventory.py`)
Executes 100% read-only, metadata-only discovery via Cloud Asset Inventory (`readMask=*`), IAM v1, and Cloud Audit Logs — **never calling `secretmanager.versions.access` or `apikeys.keys.getKeyString`**:
- **Accounts & Service Accounts:** Classifies every human, group, domain, external, consumer Gmail, convenience ACL, custom SA, and Default Compute/AppEngine SA, flagging standing 24/7 admin reach, SA impersonation reach, and Secret/KMS access.
- **Cryptographic Keys & Secrets:** Inventories `USER_MANAGED` vs. `SYSTEM_MANAGED` SA keys (`age_days`, `keyOrigin`), Secret Manager secrets (`AUTOMATIC` vs. `USER_MANAGED` replication, CMEK vs. Google encryption, rotation policy, enabled versions, and IAM accessors), Cloud KMS `KeyRing` & `CryptoKey` rotation (`<=90d` symmetric SLA, `HSM` vs. `SOFTWARE` protection, and KMS Admin + Decrypter Separation-of-Duties conflicts), Google Cloud API Keys restriction modes, Custom IAM Role escalation permissions, and Workload Identity Pool CEL `attributeCondition` posture.
